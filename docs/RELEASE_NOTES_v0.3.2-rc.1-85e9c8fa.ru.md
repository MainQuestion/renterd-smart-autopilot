# renterd v0.3.2-rc.1-85e9c8fa — Release Notes

## Исправление Smart Autopilot: прунинг контрактов в Gouging-паузе

### Проблема

Контракты, переведённые Smart Autopilot в Gouging-паузу, могли сохранять на хостах физические данные, которые уже не были нужны renterd. Записи о ссылках на эти данные удалялись из базы, но сам прунинг не выполнялся. На момент расследования это затрагивало около **8,1 ГБ на четырёх контрактах** (ID 38, 71, 68 и 69).

Причина состояла из двух частей:

- контракты в Gouging-паузе не попадали в список кандидатов на прунинг;
- общая проверка Gouging блокировала прунинг из-за превышения лимитов хранения, загрузки или скачивания, хотя для операции прунинга важны собственные ограничения стоимости освобождения сектора и общие ограничения контракта.

### Что исправлено

- В Smart Active контракты со Smart-состоянием `paused` и причиной `gouging` теперь могут попадать в кандидаты на прунинг, включая контракты в состоянии legacy.
- Для таких контрактов решение о возможности прунинга учитывает `PruneErr` и `GougingErr`. Превышение лимитов storage/upload/download само по себе больше не блокирует прунинг.
- Для остальных контрактов сохраняется прежняя проверка Gouging.
- Обычные офлайн-контракты `Paused`, контракты в процессе drain и другие состояния не добавляются в список кандидатов.
- В режимах Original и Smart Shadow поведение не меняется.
- Добавлены тесты для принятия решения по Gouging и отбора контрактов; при прунинге Gouging-паузы записывается Info-лог с ID контракта, хостом и объёмом.

### Результат

Smart Autopilot может освобождать уже неиспользуемые данные на Gouging-приостановленных контрактах, не ослабляя проверки, непосредственно относящиеся к стоимости прунинга и допустимости контракта.

Изменение применяется только в режиме **Smart Active**.
