# renterd Smart Autopilot

[English](README.md) | [Українська](README.uk.md) | Русский

Экспериментальная сборка Smart Autopilot для [Sia renterd](https://github.com/SiaFoundation/renterd).

> [!WARNING]
> Это неофициальная экспериментальная сборка и **не является официальным релизом Sia Foundation**.
>
> Проект сейчас находится на стадии **alpha**, поэтому его следует использовать с резервными копиями и осторожностью.

## Обзор

**renterd Smart Autopilot** — это экспериментальное расширение логики управления хостами в Sia `renterd`.

Долгосрочная цель — уйти от зависимости от одного агрегированного показателя host score и перейти к более прозрачному профилю хоста, где хосты оцениваются по нескольким независимым направлениям:

- Надёжность
- Производительность
- Ресурсы
- Экономика
- Риск / залог
- Техническая совместимость
- Сетевая независимость

Эти группы не обязательно должны сразу сводиться к одному «магическому числу».

Например, хост может быть очень надёжным и недорогим, но иметь лишь среднюю производительность. Smart Autopilot должен сохранять это различие, а не скрывать его внутри одного общего score.

Текущий alpha-релиз содержит первую техническую основу для этой архитектуры.

## Реализованные возможности

### Настраиваемый host scoring

Несколько параметров оценки хостов renterd, которые раньше были жёстко заданы в коде, теперь можно настраивать.

Текущие параметры:

- Вес свободного места
- Экспонента штрафа за нехватку места
- Коэффициент резерва при распределении
- Экспонента штрафа за взаимодействия
- Начальный коэффициент доверия к взаимодействиям
- Возможность отключать отдельные факторы legacy host score

Значения по умолчанию предназначены для сохранения исходного поведения renterd.

В web-интерфейсе renterd добавлена отдельная страница **Scoring**.

---

### Performance Score

Добавлен отдельный **Performance Score** для хостов.

Он намеренно не входит в исходный host score renterd.

Текущая реализация использует исторические данные о производительности, включая:

- Скорость upload
- Скорость download
- Историческую скорость операций
- P95 производительности операций
- Количество накопленных данных о производительности

Производительность оценивается по скользящему историческому окну.

Это первый шаг к тому, чтобы рассматривать производительность как отдельную характеристику хоста, а не смешивать её напрямую с legacy host score.

---

### Реальная скорость upload и download

В таблице Hosts отображается фактически измеренная пропускная способность хоста:

- Upload Mbps
- Download Mbps

Реальная скорость показывается отдельно от нормализованного Performance Score.

---

### История хостов

Для будущих решений Smart Autopilot сохраняется дополнительная историческая информация:

- История скорости
- История цен
- История сканирований

Это создаёт основу для оценки поведения хоста во времени, а не только по его последнему состоянию.

---

### Paused contracts

Добавлено новое состояние контракта **Paused**.

Paused-контракты создают промежуточное состояние между здоровым активным контрактом и контрактом, который уже нужно считать плохим или непригодным.

Цель — сделать управление жизненным циклом контракта более управляемым и не сводить каждую временную проблему к бинарному решению good/bad.

---

### Улучшения web-интерфейса

Интерфейс Hosts в renterd расширен дополнительной информацией о производительности и группировкой показателей.

Также исправлена SPA-навигация, чтобы устранить ошибки порядка React hooks, которые могли возникать при переходах между страницами renterd без полной перезагрузки браузера.

## Планируемая архитектура Smart Autopilot

Дальнейшая разработка должна оценивать хосты по отдельным группам, а не только по legacy aggregate score.

### 1. Надёжность

Насколько стабильно хост работает и выполняет свои обязательства.

Возможные сигналы:

- Uptime
- Успешные и неудачные взаимодействия
- Последовательные отказы
- Возраст хоста и историческая стабильность

### 2. Производительность

Насколько быстро хост реально обслуживает запросы renter.

Возможные сигналы:

- Время отклика
- Скорость upload
- Скорость download
- P90/P95 времени операций
- Поведение очереди запросов

### 3. Ресурсы

Достаточно ли у хоста ресурсов для нужного размещения данных.

Возможные сигналы:

- Свободное место
- Использованное место
- Объём, доступный для новых контрактов
- Ограничения ресурсов или контрактов

### 4. Экономика

Ожидаемая экономическая стоимость использования хоста.

Возможные сигналы:

- Цена хранения
- Цена upload
- Цена download
- Стоимость RPC
- Цена контракта
- Ожидаемая общая стоимость хранения за срок контракта

### 5. Риск / залог

Какой финансовый и операционный риск связан с хостом.

Возможные сигналы:

- Collateral
- Достаточность залога относительно ожидаемого объёма данных
- История продления контрактов
- Риск потери средств или данных

### 6. Техническая совместимость

Соответствует ли хост протоколу и системным требованиям renterd.

Возможные сигналы:

- Версия RHP
- Принимает ли хост контракты
- Статус анонса
- Статус сканирования
- Поддержка необходимых функций

### 7. Сетевая независимость

Увеличивает ли использование этого хоста общий инфраструктурный риск вместе с другими выбранными хостами.

Возможные сигналы:

- IP-адрес
- Подсеть
- ASN
- Географическая информация, если доступна
- Пересечение инфраструктуры с другими выбранными хостами

Сетевая независимость отличается от других групп тем, что зависит не только от самого хоста, но и от всего выбранного портфеля хостов.

## Принципы разработки

Разработка следует нескольким принципам:

1. **Сначала исследовать фактическое поведение renterd, а уже потом его менять.**
2. **Не менять существующее поведение без понимания его назначения.**
3. **Сохранять пользовательскую настраиваемость там, где это практически возможно.**
4. **Отделять измеренные данные от политики принятия решений.**
5. **Не скрывать независимые характеристики хоста внутри одного score.**
6. **Использовать исторические данные там, где одного наблюдения недостаточно.**
7. **Рассматривать выбор хостов как управление портфелем, а не только как ранжирование отдельных хостов.**

## Установка

Сейчас этот репозиторий распространяет экспериментальные бинарные сборки для Windows.

Последний релиз можно скачать здесь:

https://github.com/MainQuestion/renterd-smart-autopilot/releases

Перед заменой существующей установки renterd:

1. Остановите renterd.
2. Сделайте резервную копию текущего `renterd.exe`.
3. Сделайте резервную копию важных данных и баз renterd.
4. Распакуйте архив релиза.
5. Замените существующий исполняемый файл на `renterd.exe` из архива.
6. Запустите renterd и проверьте лог на наличие ошибок миграции или запуска.

При замене только исполняемого файла не нужно удалять существующие конфигурационные файлы или базы данных.
